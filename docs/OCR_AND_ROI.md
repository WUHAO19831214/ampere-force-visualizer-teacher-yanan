# OCR 与 ROI 校准

## 1. 两层 ROI

`RoiConfig` 使用 0 到 1 的归一化坐标：

```ts
interface Rect {
  x: number;
  y: number;
  width: number;
  height: number;
}
```

- `displayRoi`：标记完整通道区域，帮助教师识别 F1/F2/F3 或 Fy/Fz。
- `ocrRoi`：真正送入识别器的数字区域，应尽量只包含数字、负号和小数点。

归一化坐标使 ROI 能随视频分辨率缩放，但窗口布局、DPI 或软件界面变化后仍需重新校准。

## 2. 当前识别器状态

| 方法 | 状态 | 用途 |
| --- | --- | --- |
| mock | 已实现 | 调试，不得作为实测证据 |
| tesseract | 已实现 | 本地 OCR 主路径 |
| template-digit | 占位/待完善 | 固定字体模板方案 |
| cnn-onnx | 占位/待接模型 | 轻量模型方案 |

Tesseract 使用英文模型、单行/单词/单块 PSM，并限制字符白名单为 `0123456789.-`。失败不会自动回退到 mock。

## 3. 推荐校准步骤

1. 用 display ROI 框住完整通道。
2. 用 OCR ROI 只框数字；排除单位、边框、标签和曲线。
3. 查看裁剪原图与预处理图。
4. 测试 `auto`、灰度阈值、高对比度、反色或彩色数字模式。
5. 检查 rawText、提取值、confidence、durationMs。
6. 从 1 到 2 Hz 起步，稳定后再提高。
7. 保存 ROI 配置、屏幕分辨率和实验软件缩放比例。

## 4. 有效性判据

建议把验证拆为：

- 字符级：rawText 是否包含完整符号与小数点；
- 数值级：与屏幕人工读数是否一致；
- 物理级：是否落入范围、跳变是否合理；
- 时序级：在连续采样中是否稳定。

confidence 只是 OCR 引擎置信度，不等同于物理测量不确定度。

## 5. 验证数据建议

建立人工标注截图集，覆盖正负数、不同小数位、边界值、背景线、窗口缩放和不同显示器。报告准确率时同时给出样本数、完全正确率、数值误差、失败率和平均耗时。
